## Review practice

I keep notes on pull requests I read, even when I do not comment. These notes live in the [`review-notes/`](./review-notes/) folder.

Each note follows a consistent structure:

- What does this PR claim to do?
- Does the change actually accomplish that?
- What edge cases or risks are present?
- Would I approve, request changes, or comment? Why?
